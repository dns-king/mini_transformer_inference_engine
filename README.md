# Mini Transformer Inference Engine

A deliberately small, dependency-free C++20 decoder-only Transformer inference engine for learning CPU autoregressive inference. It uses the standard library only, runs entirely offline, and is designed to be comfortable on a Windows x64 laptop CPU. It is a systems demonstration, not a useful language model: its bundled weights are deterministic random values and its output has no linguistic quality claim.

## Build and run

Use CMake and a C++20 compiler; no Python, GPU, network request, package manager, model download, or hosted service is required.

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
.\build\Release\mtie_make_demo.exe demo
.\build\Release\mtie_cli.exe --model demo/demo.mtie --tokenizer demo/demo.tok --text hello --max-tokens 12 --temperature 0.7 --top-k 4 --seed 7
```

`mtie_cli --help` lists options. `--ids 7,6,9,9,10` accepts token IDs instead of text. Temperature zero is greedy decoding; a positive temperature plus `--top-k` samples reproducibly from the supplied seed. The CLI reports parameter count, float32 weight memory, prompt time, and mean full-recompute generation time per token.

## Architecture and shapes

The bundled model is `V=16`, `D=16`, `H=4`, `L=2`, `F=32`, and maximum context `T=64`, requiring about 23 KiB of float32 weights. For token IDs `[T]`, token and learned position embeddings are `[T,D]`. Every layer applies pre-layer-normalized multi-head attention, residual addition, then pre-layer-normalized feed-forward network and residual addition:

```
Q=X Wq, K=X Wk, V=X Wv                 [T,D] x [D,D]
head_i = softmax((Qi Ki^T)/sqrt(D/H) + causal_mask) Vi
X = X + concat(heads) Wo
X = X + W2 ReLU(W1 LN(X))
logits = W_vocab LN(X_last)                         [V]
```

The causal mask is implemented by evaluating attention scores for position `t` only over positions `0..t`; future scores are never materialized, which is equivalent to adding negative infinity before softmax. Layer normalization uses population variance and epsilon `1e-5`. Computation and stored weights use IEEE float32; softmax's sum and layer-norm statistics use double accumulation where practical. Softmax subtracts the maximum logit before exponentiation.

Autoregressive generation follows `p(x_1..x_n)=product_t p(x_t | x_<t)`: each sampled token is appended and logits are recomputed over the current prefix. This is clear but intentionally does not include a KV cache, so fair benchmarks should state prompt length, generated-token count, warm-up policy, compiler/configuration, and that timings include full-prefix recomputation per generated token. Tiny random weights exercise data flow and numerical code, not language capability.

## Portable local formats

`*.mtie` is binary little-endian MTIE weight format version 1. Its header is: NUL-terminated `MTIEWEIGHT`, `uint32 version`, then six `uint32`s: vocabulary, model width, head count, layer count, FFN width, and max context. Each tensor follows as `uint64 element_count` then contiguous row-major float32 values, in this order: token embeddings, positional embeddings, for each layer `Wq,Wk,Wv,Wo,W1,W2,LN1 gain/bias,LN2 gain/bias`, final LN gain/bias, and final vocabulary projection. Loader validation rejects bad magic/version, zero or non-divisible head dimensions, truncated data, and incompatible tensor/vector sizes.

`*.tok` is UTF-8 line text: first line `MTIETOK1`, then one token per following nonempty line; the token index is its ID. The demo tokenizer is character-level and maps unknown bytes to ID 0. The CLI rejects a tokenizer/model vocabulary-count mismatch.

An external exporter can write the documented format, but conversion is deliberately outside the core runtime; loading is local and has no dependency beyond C++.

## Tests and limits

`mtie_tests` checks stable softmax for large logits, layer-normalization centering, attention/logit shape, deterministic seeded sampling, and prefix repeatability—the causal invariant that logits for a prefix are not affected by tokens which have not yet been appended. The runtime's bounded `0..t` attention loop is the corresponding mask implementation. It also validates serialized tensor shapes while loading.

This implementation favors readable scalar code. It has no batching, threading, SIMD kernels, KV cache, BPE tokenizer, training, quantization, or production throughput guarantees. The test model is generated by `mtie_make_demo`; its fixed seed provides identical weights across runs on standard implementations with the same generator/distribution behavior, and its exact output should not be interpreted as a quality metric.
